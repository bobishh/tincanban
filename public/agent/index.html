tincanban agent guide

Operate the same local-first workspace the user sees. Read stable IDs first, then mutate typed entities through WebMCP commands.

Core ruleRead schema.
Use IDs.

Working model

A device owns a local catalog of independent workspaces. Each workspace is one Automerge document containing its board schema, items, document templates, history, and collaboration metadata. WebMCP commands target the current workspace shown in tincanban; creating a workspace makes it current.

boardcolumnsfieldsitemsdocument templatesartifacts
  • Every entity has a stable UUID. Titles are display text and may change.
  • placement.parentId links a column to its board, an item to a column or parent item, and an artifact to its item. placement.rank orders siblings.
  • Archive marks items archived. Enable one Archive column per board to show and restore them.
  • Removing a column hides its descendants; restoring the column reveals them with their relationships intact. Broken or cyclic ancestry appears through placement issues.
  • Job search is one preset. Its lead vocabulary and pipeline are workspace-specific, never kernel assumptions.

Safe agent workflow

  1. Call list_workspaces to inspect the local catalog. Use switch_workspace with the chosen workspaceId when the task requires an existing workspace. Creating or switching changes the current workspace shown to the user.
  2. Call get_workspace_settings. Resolve board, column, field, option, and template IDs from its result.
  3. Read items with list_items or inspect one typed entity with get_entity.
  4. Use generic mutation tools. Put custom values under stable field IDs, not field titles.
  5. Re-read visible state after mutations. Treat returned IDs and CRDT heads as authoritative.

Complete workspace settings

get_workspace_settings returns settings plus heads. Settings contain formatVersion, workspace.title, the board title and item name, column colors and archive behavior, card stage buttons, aging thresholds, priorityPolicy, employee_profile, typed fields and select options, and documentTemplates. Templates belong to that workspace and describe documents generated for its items; they have no fixed CV/cover-letter kind enum.

To change the complete configuration, edit the returned object and call apply_workspace_settings with those heads as expectedHeads. The apply is one validated CRDT transaction. Omitted columns, fields, and templates are soft-archived. Existing descendants and field values remain stored.

Keep IDs returned by tincanban when editing. Omit an ID only when adding a column, field, field option, or document template. A field's valueType cannot change in place.

Mutation rules

  • Unknown fields are rejected without mutation. Send command inputs, never raw Automerge objects or changes.
  • Keep returned IDs. Names are editable labels and cannot identify an entity safely.
  • Use expectedHeads for settings writes. On a conflict, re-read settings, reapply the intended edit, and submit the new heads.
  • Use restore_and_move when an entity's former parent is archived or missing. Do not repair ancestry by recreating the entity.
  • Inspect list_placement_issues only for recovery. Normal parent/child relationships need no repair.

Sync, identity, and storage

  • Share workspaces: Sync opens with the current workspace selected. Select one or more existing workspaces, then generate one invitation for that fixed set. The recipient keeps a separate person and device identity.
  • Add my device: enrolls another device under the same personal identity and shares the personal workspace catalog after mutual code approval.
  • Sync contains Participants, Rusty, Backups, and Recovery. Import as a new board belongs to the Workspaces list; export belongs to Sync → Backups.
  • Rusty stores encrypted objects without reading or classifying cards. Eligible owners automatically replace old snapshots after 8 retained objects; the replacement still contains Automerge history, so document size can grow.
  • Automerge changes sync incrementally while peer sessions are live. Workspace snapshots and trust state persist in IndexedDB.
  • A .tincanban export carries workspace data, Automerge history, and public proofs. It excludes private signing keys, the personal root, and pairing secrets.

Settings and publication

Settings uses one section list: Identity, Workspace, Document templates, Priority rules (job-search boards), and settings.json. Identity saves photo and name together and contains encrypted identity recovery. Workspace shows saved/sync status, automations, Public board access, and device diagnostics. Diagnostic consent applies across workspaces on this device.

Public board is an owner-only switch with a scope confirmation. Publication creates a saved public copy; later edits remain private until Update public copy. Withdrawing removes access to that copy and its files, but cannot recall downloaded copies. Publication is separate from workspace settings and has no WebMCP tool.

CLEF supplies vacancy assessments through approved automations. Automatic priority computes fit and priority from those saved assessments; it does not start or stop CLEF. Job match uses company recognition 20%, stability 20%, stack 30%, and work profile 30%. Missing evidence contributes no points. Profile edits invalidate old stack/work comparisons; historical cards are not automatically reclassified. Preserve existing weighted rules unless the user requests conversion.

Board cards drag with their full content. Select text and open contextual discussions inside a card’s details.

Run locally

Install pinned dependencies with npm ci, then start Vite with npm run dev. Workspaces remain in that browser profile's IndexedDB. Production builds use npm run build. Rust is needed only when rebuilding the canonical transport after transport source changes.
